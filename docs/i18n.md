# Internationalization

This project uses a lightweight in-app dictionary approach for UI strings.

## Supported Locales
- English (`en`) is the default and reference locale.
- Chinese Simplified (`zh-CN`) and Chinese Traditional (`zh-TW`) are bundled.

## How It Works
- Strings live in `src/shared/i18n.ts`.
- Use `t('key')` to fetch a string in UI components.
- With the default `uiLanguage: 'auto'`, the locale is resolved from
  `navigator.language` (zh-TW/HK/Hant → `zh-TW`, other zh → `zh-CN`, else `en`)
  and falls back to English.

## UI Language Override
- `global.uiLanguage` (`'auto' | 'en' | 'zh-CN' | 'zh-TW'`, default `'auto'`)
  pins the UI language for every surface: popup, options page, and the video
  widget. Unknown values degrade to `'auto'` in `mergeGlobalRaw`.
- `setUiLocale()` (src/shared/i18n.ts) sets the module-level locale consumed
  by `t()`. Each entrypoint keeps it in sync with the stored config:
  popup/options hydrate it after `getConfig`, and the content script's
  `applyWidgetSettings` mirrors it on startup and on every sync-config
  `storage.onChanged`, so a change in the options page applies to open
  surfaces without a reload.
- The language selector lives on the options page (summary card grid).

## Adding a New Language
1. Add a new locale dictionary in `src/shared/i18n.ts`.
2. Update the `Locale` union type, `messagesByLocale`, and
   `UI_LANGUAGE_VALUES` (the options selector follows it automatically).
3. Add any new keys to the English dictionary to keep coverage complete;
   the key-set consistency test (src/shared/i18n.test.ts) enforces parity.
